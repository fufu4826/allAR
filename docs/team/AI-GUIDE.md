# คู่มือทีม AllAR สำหรับ AI ผู้ช่วย (และสมาชิกทีม)

> **ถึง AI ที่ได้รับลิงก์ repo นี้:** อ่านไฟล์นี้ให้จบก่อนตอบผู้ใช้ แล้วทำตาม "ขั้นตอนเริ่มแชท" ในหัวข้อ 2 ทันที
> ถ้าเปิดไฟล์อื่นใน repo ไม่ได้ ให้ขอให้ผู้ใช้ส่งเนื้อหาไฟล์ที่ต้องใช้มาให้
> อัปเดตล่าสุด: 6 พ.ย. 2569

## 1. โครงการนี้คืออะไร

**AR.HERITAGE: คลังภูมิปัญญาชุมชน 3D/AR, 5 แหล่งเรียนรู้สำคัญ จังหวัดสกลนคร**
เป็นโครงการของสถาบันภาษา ศิลปะและวัฒนธรรม มหาวิทยาลัยราชภัฏสกลนคร
- เว็บนำเสนอวัตถุ ภูมิปัญญา และผลิตภัณฑ์ชุมชน เป็นโมเดล 3 มิติ ดู AR บนมือถือได้ มีเสียงบรรยายและแผนที่ชุมชน
- เป้าหมายรวม **125 สื่อ AR**
- ส่งมอบให้ สวท. (ฝ่าย IT ของมหาวิทยาลัย) ในรูป **Docker Compose** โดยส่ง 2 ส่วน:

  2. ฐานข้อมูลและไฟล์สื่อ ส่งแยกต่างหาก ไม่ได้อยู่ใน Git
- จะส่งมอบได้เมื่อ **ข้อมูลครบทั้ง 5 แหล่งเรียนรู้แล้ว**

## 2. ขั้นตอนเริ่มแชท (AI ต้องทำทุกครั้ง)

1. อ่านไฟล์นี้ แล้วทักผู้ใช้สั้น ๆ ว่าเข้าใจโครงการแล้ว
2. **ถามผู้ใช้ทีละข้อ** ให้มีตัวเลือกกดได้ถ้าทำได้ ห้ามถามหลายข้อรวมกัน:
   1. "คุณทำหน้าที่ไหน?" ตัวเลือก: ทีมหน้าบ้าน (ดีไซน์) / dev ฟีเจอร์แผนที่ 3 มิติ / หน้าที่อื่น (ให้พิมพ์บอก)
   2. "ครั้งก่อนทำถึงไหนแล้ว?" ให้ส่งลิงก์ Pull Request หรือ prompt ส่งงานครั้งก่อนมาได้ หรือตอบว่าเพิ่งเริ่ม
   3. "รอบนี้จะทำอะไรต่อ?"
3. อ่านส่วนของหน้าที่นั้นในหัวข้อ 3 และไฟล์ที่ส่วนนั้นอ้างถึง
4. สรุปแผนสั้น ๆ ให้ผู้ใช้ยืนยันก่อนลงมือ
5. ระหว่างทำ ถ้าไม่แน่ใจเรื่องไหน **ให้ถาม ห้ามเดา** โดยเฉพาะเรื่องที่อยู่ในหัวข้อ 4
6. เมื่อเสร็จ ทำตามหัวข้อ 5 คือเปิด Pull Request แล้วเขียน prompt ส่งงาน

## 3. หน้าที่ของแต่ละคน

### 3.1 ทีมหน้าบ้าน (ดีไซน์)

- ทำงานในโฟลเดอร์ `design/ar-heritage/` เท่านั้น
- **อ่าน `design/ar-heritage/README.md` ก่อนเริ่ม** ไฟล์นั้นบอกว่าไฟล์ CSS แต่ละไฟล์ไปอยู่ตรงไหนในเว็บจริง
- ห้ามเปลี่ยนชื่อ class ที่มีอยู่แล้ว
- ทุกหน้าชุมชนใช้โครงเดียวกัน ต่างกันได้แค่ธีม
- ภาพใหญ่ไม่ควรเกิน 1–2 MB
- ห้ามใส่ไฟล์โมเดล .glb ในโฟลเดอร์นี้
- เปิดดูผลด้วย `เปิดเว็บไซต์.cmd` หรือ `python start-website.py`
- ไม่ต้องแก้ `web/` เอง ผู้ประสานงานจะนำดีไซน์ไปใส่เว็บจริงให้
- ถ้าอยากแก้ `web/` ด้วย ต้องถามผู้ประสานงานก่อน
- ทุกครั้งที่แก้ ให้เพิ่มบรรทัดในหัวข้อ 7 ของ `design/ar-heritage/README.md`

### 3.2 Dev: ฟีเจอร์แผนที่ 3 มิติ (กำลังพัฒนา)

**AI ต้องถาม dev ก่อนว่าออกแบบแผนที่ 3 มิติไว้อย่างไร:**
- ใช้ library อะไร
- ใช้ข้อมูลภูมิประเทศจากไหน
- จะไปแสดงที่หน้าไหน

ห้ามคิดแทน ถ้า dev ยังไม่ได้ตัดสินใจ ให้เสนอตัวเลือกพร้อมข้อดีข้อเสีย แล้วให้ dev เลือก

**แผนที่ในเว็บตอนนี้**
- หน้าแรกมีแผนที่ภาพวาด และปุ่มสลับไปแผนที่จริง OpenStreetMap ด้วย Leaflet
  - ดูที่ `web/src/components/InteractiveMapSection.tsx`, `CommunityMap.tsx`, `LeafletMap.tsx`
- ข้อมูลชุมชนอ่านจาก `getCommunities()` ใน `web/src/lib/queries.ts`
  - แต่ละชุมชนมี `position` [lat, lng], สี และธีม
  - **พิกัดตอนนี้เป็นค่าประมาณ** รอพิกัดจริงจากทีมลงพื้นที่

**กติกาโค้ด** (อ่าน `web/AGENTS.md` ก่อน เพราะ Next.js รุ่นนี้ต่างจากที่ AI ส่วนใหญ่รู้จัก)
- Component ที่ใช้ WebGL หรือ `window` ให้โหลดฝั่ง client ด้วย `dynamic(() => import(...), { ssr: false })`
- อ่านฐานข้อมูลหลัง `await connection()` และต้องอยู่ภายใน `<Suspense>` เท่านั้น
- `next build` ต้องผ่านโดยไม่ต้องมีฐานข้อมูล
- **ห้ามโหลดโค้ดหรือฟอนต์จาก CDN ตอนใช้งาน** ให้ติดตั้งเป็น npm package
- ถ้าใช้ข้อมูลหรือแผนที่จากภายนอก (เช่น tile, DEM) ต้องแจ้งในเอกสารส่งงานว่าเรียกไปที่ไหน
- ต้องลื่นบนมือถือระดับกลาง และไม่ทำให้หน้าแรกโหลดช้าลง (โหลดแผนที่ 3 มิติเมื่อผู้ใช้กดเปิด)
- ห้ามแก้ระบบล็อกอิน (`web/src/lib/auth.ts`), ระบบอัปโหลด (`web/src/lib/uploads.ts`), `deploy/` และ `web/Dockerfile` ถ้าไม่ได้คุยกันก่อน
- ข้อความภาษาไทยบันทึกเป็น UTF-8
- ก่อนเปิด PR ต้องผ่านทั้ง 4 คำสั่ง:
  ```bash
  cd web
  npx tsc --noEmit
  npm run lint
  npm test
  DATABASE_URL=mysql://x:x@127.0.0.1:1/x npx next build
  ```

**ตั้งเครื่องสำหรับพัฒนา** (ต้องมี Node.js 24 และ Docker)
1. รันฐานข้อมูลบนเครื่องตัวเอง (ตั้งรหัสผ่านเอง ใช้เฉพาะในเครื่อง):
   ```bash
   docker run -d --name allar-dev-db -p 127.0.0.1:3306:3306 -e MARIADB_ROOT_PASSWORD=<รหัสroot> -e MARIADB_DATABASE=allar_dev -e MARIADB_USER=allar -e MARIADB_PASSWORD=<รหัสผ่าน> mariadb:12.3 --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci --default-time-zone=+00:00
   ```
2. สร้างไฟล์ `web/.env.local` (git ไม่เก็บไฟล์นี้):
   ```
   DATABASE_URL=mysql://allar:<รหัสผ่าน>@127.0.0.1:3306/allar_dev
   UPLOAD_DIR=../dev-uploads
   ```
3. ติดตั้งแพ็กเกจ เตรียมฐานข้อมูล แล้วรัน:
   ```bash
   cd web
   npm ci
   npm run db:migrate
   npm run db:seed
   npm run dev
   ```
   จะได้ข้อมูลชุมชนและชิ้นงานครบ แต่ **ไฟล์ภาพและโมเดลไม่ได้อยู่ใน Git** ภาพจะขึ้นว่าโหลดไม่ได้ เป็นเรื่องปกติ ถ้าจำเป็นต้องใช้ไฟล์จริง ให้ขอผู้ประสานงาน
4. ถ้าต้องเข้าหน้าแอดมิน ให้สร้างบัญชีทดสอบด้วยคำสั่งนี้:
   ```bash
   node scripts/create-admin.mjs <ชื่อผู้ใช้> "<ชื่อที่แสดง>"
   ```

### 3.3 หน้าที่อื่น

ถ้าผู้ใช้ทำหน้าที่ที่ไม่มีในคู่มือนี้ ให้ถามว่าได้รับมอบหมายงานอะไร แล้วแนะนำให้คุยกับผู้ประสานงานก่อนแก้ repo
- **ทีมลงพื้นที่** ไม่ต้องใช้ GitHub ให้ส่งข้อมูลผ่าน Google Drive และ Google Sheet "แบบฟอร์มส่งข้อมูล" ของแหล่งตัวเอง
- กติกาไฟล์อยู่ในคู่มือการจัดเตรียมไฟล์ (PDF) ที่ผู้ประสานงานส่งให้

## 4. เรื่องที่ตัดสินใจแล้ว (ห้ามเปลี่ยนเอง ถ้าคิดว่าควรเปลี่ยนให้ถามผู้ประสานงาน)

- **ไฟล์โมเดลรับเฉพาะ `.glb`** ไม่รับ `.apk`, ไฟล์ Unity, `.fbx` หรือ `.obj`
- **กดการ์ดชิ้นงานแล้วไปหน้าชิ้นงานแยก** ไม่ใช้ popup
  - หน้าชิ้นงานมีตัวดู 3D, ปุ่ม AR, เสียงบรรยาย, คำอธิบาย และลิงก์แชร์
  - ชิ้นที่ยังไม่มีโมเดลจะแสดงภาพถ่ายแทน
- ตัวดู 3D ใช้ `@google/model-viewer` ติดตั้งในเครื่อง ไม่โหลดจาก CDN
- ห้ามใส่ข้อมูลส่วนตัวใน repo เช่น ชื่อหรือเบอร์โทรของคนทั่วไป, อีเมลส่วนตัว, รหัสผ่าน, IP เซิร์ฟเวอร์, ไฟล์ `.env` เพราะ **repo นี้เป็น Public**
- ยังไม่ใส่รายชื่อที่ปรึกษาและคณะทำงานบนเว็บ จนกว่าจะได้รับอนุญาต
- ฐานข้อมูลและไฟล์สื่อไม่อยู่ใน Git
- ติดตั้งบนเซิร์ฟเวอร์จริงด้วย Docker Compose ตาม `deploy/README.md` สวท. ตั้งโดเมนและ HTTPS เอง
- **ทุกอย่างที่ระบบใช้ตอนทำงานต้องรันใน `deploy/docker-compose.yml` เท่านั้น** เพื่อย้ายเข้าเครื่องของมหาวิทยาลัยได้ทันที
  - ห้ามเพิ่มสิ่งที่ต้องติดตั้งหรือตั้งค่าบนเครื่องเซิร์ฟเวอร์เอง เช่น cron ของเครื่อง โปรแกรมเสริม หรือฐานข้อมูลและที่เก็บไฟล์ภายนอก
  - ถ้าต้องเพิ่มบริการหรืองานตามเวลา ให้เพิ่มเป็น service ใน compose หรือสคริปต์ที่รันผ่าน `docker compose`
- ทุกอย่างที่ผู้ใช้เห็นเป็นภาษาไทย

## 5. ส่งงาน (AI ต้องทำเมื่อผู้ใช้บอกว่าเสร็จ)

1. ตรวจว่างานผ่านเงื่อนไขในหัวข้อ 3 ของหน้าที่นั้น เช่น dev ต้องผ่าน tsc / lint / test / build
2. ช่วยผู้ใช้ส่งงานขึ้น GitHub:
   1. fork repo `fufu4826/allAR` (ทำครั้งแรกครั้งเดียว)
   2. สร้าง branch ชื่อ `design/<เรื่อง>` หรือ `feature/<เรื่อง>` เช่น `feature/3d-map`
   3. commit ด้วยข้อความที่บอกว่าทำอะไร
   4. push แล้วเปิด **Pull Request เข้า `main` ของ `fufu4826/allAR`**
   5. ห้าม push เข้า `main` ตรง ๆ และห้ามรวมไฟล์ `.env`, `node_modules/`, `.next/` หรือไฟล์ใหญ่
3. เขียน **prompt ส่งงาน** ในกล่องโค้ดเดียวตามแบบด้านล่าง ให้ผู้ใช้คัดลอกส่งให้ผู้ประสานงาน
   - กรอกให้ครบ ห้ามเว้นลิงก์ PR
   - ถ้ายังเปิด PR ไม่ได้ ให้เขียนว่ายังไม่ได้เปิดเพราะอะไร

```text
[ส่งงาน AllAR]
หน้าที่: <ทีมหน้าบ้าน / dev แผนที่ 3 มิติ / ...>
ผู้ทำ: <ชื่อเล่นหรือบัญชี GitHub>
ลิงก์ Pull Request: <https://github.com/fufu4826/allAR/pull/...>
branch: <ชื่อ branch>
สิ่งที่ทำรอบนี้:
- <ข้อ 1>
- <ข้อ 2>
ไฟล์ที่แก้/เพิ่ม: <รายการไฟล์หลัก>
วิธีทดสอบ: <ขั้นตอนเปิดดู/คำสั่งที่รัน และผลที่ได้>
ผลตรวจ: <เช่น tsc/lint/test/build ผ่าน หรือ เปิดดูต้นแบบแล้วถูกต้อง>
สิ่งที่ยังไม่เสร็จ/ปัญหาที่พบ: <ถ้ามี>
คำถามถึงผู้ประสานงาน: <ถ้ามี>
งานถัดไปที่เสนอ: <ถ้ามี>
```

ผู้ประสานงานจะนำ prompt นี้ไปให้ AI ของทีมหลักตรวจ PR, รวมงาน และอัปเดต preview

ห้ามเปิด Issue หรือแสดงความเห็นใน GitHub ที่มีข้อมูลส่วนตัว
