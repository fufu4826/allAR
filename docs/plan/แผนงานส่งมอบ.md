### วงจรการทำงานของแต่ละงาน (ทุกงานของ Codex และ agy)
```
Claude เขียน prompt ──► Codex/agy เขียนโค้ดใน worktree ──► Claude ตรวจ
                                                    │ ผ่าน → merge เข้า main + รายงานคุณ
```

## 2. การตัดสินใจทางเทคนิค (ล็อกแล้ว)

| เรื่อง | ใช้ | เหตุผล |

| ไฟล์สื่อ | โฟลเดอร์ `UPLOAD_DIR` (volume `uploads`) เสิร์ฟผ่าน route `/uploads/...` รองรับ Range | เจ้าหน้าที่ backup ง่าย ไม่พึ่งบริการภายนอก |

| พอร์ต | เว็บ `127.0.0.1:${WEB_PORT:-3000}` · DB/phpMyAdmin ไม่เปิดออกนอก container | เจ้าหน้าที่ต่อ reverse proxy/HTTPS เอง |

## 3. แผนงานเป็นเฟส

### เฟส 0 — เตรียม repo (Claude) · ~0.5 วัน
- รวม `web/`, `deploy/`, `docs/`, `tools/` เป็น git repo เดียวที่ `D:\allAR` (ย้ายประวัติจาก `web/.git`)
- `.gitignore`: `.env`, `node_modules`, `.next`, `uploads/`, `backups/`, `data-bundle/`, `*.sql.gz`
- สร้าง branch `main` + commit แรก (ยังไม่ push)
- **ฐานทดสอบ** (เครื่องคุณไม่มี Docker): สร้าง `allar_dev` + ผู้ใช้ `allar_dev` ที่มีสิทธิ์เฉพาะฐานนี้ บนโน้ตบุ๊ก · ต่อจากเครื่องคุณผ่าน SSH tunnel `127.0.0.1:13306` · ค่าเชื่อมต่อเก็บใน `web/.env.local` (อยู่ใน .gitignore) · ฐาน `allar_db` ไม่ถูกแตะระหว่างพัฒนา
- **เกณฑ์รับ:** `git status` สะอาด, ไม่มีไฟล์ลับใน repo, `web` ต่อ `allar_dev` ผ่าน tunnel ได้
- **คุณ:** เปิดโน้ตบุ๊กค้างไว้ระหว่างพัฒนา

### เฟส 1 — ฐานข้อมูล (**Codex C1** → Claude ตรวจ) · ~1 วัน
- schema + migration + seed ภูพานจาก `web/src/data/phuphan.json`
- **เกณฑ์รับ:** `npm run db:migrate && npm run db:seed` บน MariaDB ว่าง ได้ 5 ชุมชน / 10 แหล่งเรียนรู้ / 41 ชิ้นงาน, รันซ้ำไม่ซ้ำข้อมูล

### เฟส 2 — ไฟล์สื่อภูพาน (**agy A1** → Claude ตรวจ+รัน) · ~1 วัน
- ดาวน์โหลดจาก R2 → `data-bundle/originals/` · ย่อ → `data-bundle/uploads/` · อัปเดต path ใน seed
- **เกณฑ์รับ:** ครบ 41 โมเดล + รูป + เสียง 20 ไฟล์, รูป ≤ 1600px, โมเดลรวมเล็กลง ≥ 50%, Claude เปิดดูสุ่ม 5 ชิ้นว่าหน้าตาไม่เพี้ยน
- **คุณ:** ดูหน้าตาโมเดลที่ย่อแล้ว 3–5 ชิ้น ยืนยันว่ารับได้

### เฟส 3 — หน้าเว็บอ่านจากฐานข้อมูล (**Codex C2** → Claude ตรวจ) · ~1 วัน
- เปลี่ยน `communities.ts` เป็นฟังก์ชันอ่าน DB, route `/uploads/[...path]`, `/api/health`
- **เกณฑ์รับ:** ทุกหน้าที่มีอยู่แสดงเหมือนเดิม แต่ข้อมูลมาจาก DB และไฟล์มาจาก `/uploads`

### เฟส 4 — ระบบล็อกอิน + สิทธิ์ + ตรวจไฟล์อัปโหลด (**Codex C3** → Claude ตรวจความปลอดภัย) · ~1 วัน
- `/admin/login`, session, logout, จำกัดล็อกอินผิด 5 ครั้ง/15 นาที, CSRF (Server Actions + Origin check), audit log
- คำสั่งสร้างแอดมินคนแรก: `docker compose exec web node scripts/create-admin.mjs`
- **เกณฑ์รับ:** เข้า `/admin/*` ไม่ได้ถ้าไม่ล็อกอิน, รหัสผ่านเก็บเป็น argon2id, ทดสอบล็อกอินผิด 6 ครั้งแล้วถูกล็อก

### เฟส 5 — หน้าแอดมินจัดการเนื้อหา (**agy A2** → Claude ตรวจ) · ~2 วัน
- CRUD ชุมชน / แหล่งเรียนรู้ / ชิ้นงาน, อัปโหลด .glb/.usdz/รูป/เสียง, จัดการผู้ดูแล, หน้า audit log
- agy เรียกใช้ `requireAdmin` / `audit` / `saveUpload` จาก C3 เท่านั้น ห้ามเขียนส่วนความปลอดภัยเอง
- **เกณฑ์รับ:** แอดมินเพิ่มชุมชนที่ 2 พร้อมชิ้นงาน 1 ชิ้น (มีโมเดล+เสียง) ได้ครบโดยไม่แตะโค้ด แล้วหน้าเว็บแสดงทันที

### เฟส 6 — Docker ชุดส่งมอบ (**Codex C4** → Claude ทดสอบบนโน้ตบุ๊ก) · ~1 วัน
- `web/Dockerfile` (multi-stage, standalone, non-root), `deploy/docker-compose.yml` ฉบับสมบูรณ์, container `backup` (DB + uploads, เก็บ 30 วัน), healthcheck ทุกตัว
- **เกณฑ์รับ:** บนโน้ตบุ๊ก (เครื่องคุณไม่มี Docker) `docker compose up -d` จากศูนย์ในโฟลเดอร์ใหม่ → เว็บขึ้น, migrate อัตโนมัติ, backup รันได้, restore ได้

### เฟส 7 — ทดสอบบนโน้ตบุ๊ก (Claude + คุณ) · ~0.5 วัน
- Claude: clone จาก repo บนโน้ตบุ๊ก → ทำตามคู่มือทุกบรรทัด **เหมือนเป็นเจ้าหน้าที่** → จดทุกจุดที่ติด แล้วแก้คู่มือ
- คุณ: เปิดเว็บจากมือถือในเครือข่ายเดียวกัน ทดสอบ 3D/เสียง (AR ต้องรอ HTTPS บนเซิร์ฟเวอร์จริง)

### เฟส 8 — ส่งมอบ (Claude เตรียม · คุณส่ง) · ~0.5 วัน
- คู่มือติดตั้งภาษาไทย `deploy/README.md` (**agy A3** ร่าง → Claude ตรวจทุกคำสั่งว่ารันได้จริง)
- `data-bundle/allar_db.sql.gz` + `data-bundle/uploads.zip` + checksum SHA-256
- Claude สร้าง repo Public + push (**ถามคุณก่อน push**) · คุณส่งลิงก์ repo + ไฟล์ข้อมูลให้เจ้าหน้าที่

**รวมประมาณ 8–9 วันทำงาน**

## 4. หลักการเขียน prompt ที่ใช้สั่ง Codex และ agy

ทุก prompt มีโครงเดียวกัน 8 ส่วน เพราะ Codex และ agy **ไม่เห็นบทสนทนานี้** และทำงานดีที่สุดเมื่อขอบเขตชัด (prompt เขียนเป็นภาษาอังกฤษเพื่อให้ทำตามได้แม่น แต่สั่งให้ UI และคู่มือเป็นภาษาไทย):

1. **บทบาท** — บอกว่าเป็นใคร ทำงานในโปรเจกต์อะไร
2. **บริบท** — สิ่งที่มีอยู่แล้ว, path จริง, เวอร์ชันไลบรารี, ข้อควรระวังของ Next.js 16 (ต้องอ่าน `web/AGENTS.md` และ `web/node_modules/next/dist/docs/`)
3. **เป้าหมาย** — ผลลัพธ์ปลายทางในประโยคเดียว
4. **ขั้นตอน** — ลำดับงานเป็นข้อ ๆ
5. **ข้อกำหนด/ข้อห้าม** — ไฟล์ที่ห้ามแตะ, ห้ามใส่ค่าลับ, ห้ามติดตั้งแพ็กเกจนอกรายการ, ห้าม commit
6. **ไฟล์ที่ต้องสร้าง/แก้** — รายการ path ชัดเจน
7. **เกณฑ์รับงาน** — คำสั่งที่ต้องรันผ่าน และผลที่ต้องได้
8. **รูปแบบรายงาน** — ตอบสั้น ≤ 15 บรรทัด: ไฟล์ที่แก้, คำสั่งที่รัน+ผล, สิ่งที่ไม่แน่ใจ

prompt ทั้งหมดอยู่ที่ [`docs/plan/prompts/`](prompts/) — `C1`–`C4` สำหรับ Codex, `A1`–`A3` สำหรับ agy · ทุกฉบับ Claude จะเติมรายละเอียดล่าสุดอีกครั้งก่อนสั่งจริง

**ลำดับการสั่งงาน:** C1 → (A1 ทำคู่ขนานได้) → C2 → C3 → A2 → C4 → A3 — งานถัดไปเริ่มเมื่องานก่อนหน้า merge แล้วเท่านั้น เพราะต้องใช้ไฟล์ของกันและกัน ยกเว้น A1 ที่ไม่แตะโค้ดของ C1

## 5. ความเสี่ยงที่รู้อยู่แล้ว

| ความเสี่ยง | ทางรับมือ |
|---|---|
| Codex/agy เขียนโค้ด Next.js แบบเวอร์ชันเก่า | บังคับอ่าน docs ใน `node_modules/next/dist/docs/`, Claude ตรวจ build ทุกงาน |
| Codex sandbox ไม่มีเน็ต/ต่อ DB ไม่ได้ | Claude ติดตั้งแพ็กเกจให้ก่อน และรันเกณฑ์รับงานที่ต้องใช้ DB เอง |
| ย่อโมเดลแล้วหน้าตาเพี้ยน | เก็บต้นฉบับ, คุณดูรับรองก่อน, ปรับค่าเป็นรายชิ้นได้ |
| โน้ตบุ๊ก RAM ว่าง 1.7 GB build ไม่ไหว | build image บนเครื่องผมแล้ว `docker save` ส่งไป หรือให้ compose build บนเซิร์ฟเวอร์จริง |
| repo Public รั่วค่าลับ | `.gitignore` + Claude สแกนหา secret ก่อน push ทุกครั้ง |
| เซิร์ฟเวอร์จริงไม่รู้ว่า OS อะไร | ทุกอย่างอยู่ใน container, ไม่มีสคริปต์ PowerShell/Task Scheduler ในชุดส่งมอบ |
